# Trading Journal

Личный трейд-журнал с риск-менеджментом на одного пользователя.
Next.js (App Router) + Postgres (Neon) через Prisma, деплой на Vercel.

## Локальный запуск

```bash
npm install
cp .env.example .env   # заполнить DATABASE_URL, ANTHROPIC_API_KEY, APP_PASSWORD
npx prisma migrate dev
npx prisma db seed     # создаёт единственный Account
npm run dev
```

### Переменные окружения

| Переменная          | Назначение                                              |
| ------------------- | ------------------------------------------------------- |
| `DATABASE_URL`      | строка подключения к Postgres (Neon)                     |
| `ANTHROPIC_API_KEY` | ключ для разбора скриншотов, только на сервере           |
| `APP_PASSWORD`      | пароль для входа (MVP-заглушка вместо полноценного auth) |
| `VISION_MODEL`      | модель для разбора скриншотов, по умолчанию `claude-haiku-4-5` |

## Деплой на Vercel + Neon

1. Импортировать репозиторий в Vercel.
2. Подключить Neon через Vercel-интеграцию — она сама заводит `DATABASE_URL`.
3. Добавить `ANTHROPIC_API_KEY` и `APP_PASSWORD` в Environment Variables.
4. Задеплоить: `npm run build` прогоняет `prisma migrate deploy` перед сборкой.
5. Один раз после первого деплоя выполнить сид, чтобы появился `Account`:
   ```bash
   DATABASE_URL="<neon-url>" npx prisma db seed
   ```

## Структура

```
prisma/schema.prisma          Account / BalanceEvent / Trade / Fix
src/lib/trading-math.ts       формулы: risk, position size, закрытие сделки
src/lib/risk-budget.ts        бюджет риска и его зоны
src/app/api/**                route handlers (zod-валидация, транзакции)
src/app/(pages)               дашборд, /trades/new, /trades/[id], /trades, /settings
```

### Что важно знать про расчёты

- Все денежные вычисления идут на сервере; клиент считает live-превью тем же
  `lib/trading-math.ts` — логика не продублирована.
- `Trade` хранит снапшоты `depositAtEntry` и `feeRateAtEntry`, поэтому изменение
  настроек не меняет уже открытые сделки.
- Сделка закрывается автоматически, когда сумма `sizePct` фиксаций достигает 100:
  в одной транзакции считается результат, создаётся `BalanceEvent` типа
  `trade_settlement` и обновляется баланс аккаунта.
- Баланс нельзя изменить напрямую через `PATCH /api/account` — только через
  `BalanceEvent` или закрытие сделки.
- Параметры открытой сделки можно поправить (`PATCH /api/trades/:id`): riskAmount и
  positionSize пересчитываются, а снапшоты депозита и комиссии остаются прежними.
  У закрытой сделки правка запрещена.
- `realizedRR` — знаковый R-мультипликатор `netPnL / riskAmount`. Это осознанное
  отступление от формулы раздела 4 ТЗ, которая брала модуль хода цены и поэтому
  давала убыточной сделке положительный R:R.
- Скриншоты разбирает модель из `VISION_MODEL` (по умолчанию `claude-haiku-4-5`).
  Без `ANTHROPIC_API_KEY` приложение работает полностью, кроме кнопки загрузки
  скриншота — она вернёт понятную ошибку, а сделка заводится руками.
- Модель сообщает роль уровня (`entry` / `stop` / `target`) и направление только
  когда это уже помечено на графике — цветом плашки на ценовой шкале или зонами
  инструмента позиции. Помеченное подставляется в поля, но остаётся в списке
  кандидатов и правится одним кликом: последнее слово за пользователем.
  Плашку текущей цены модель путает со входом, поэтому промпт явно запрещает
  роль "entry" для текущей цены, а форма дополнительно отбрасывает такой уровень.
  По умолчанию стоит `claude-haiku-4-5` — он примерно в семь раз дешевле и втрое
  быстрее. Цена решения известна и принята владельцем журнала: на замерах по
  реальному насыщенному снимку (индикаторы, сетка, несколько зон) Haiku промахнулся
  по входу в 3 попытках из 3 и путал подписи ценовой сетки с прочерченными
  уровнями, тогда как `claude-opus-5` дал 3/3. Подставленные вход и стоп всегда
  видны в списке кандидатов и правятся в один клик — на это здесь и расчёт.
- Разбор принимает и загруженный файл, и ссылку на снимок TradingView
  (`tradingview.com/x/…`): страница снимка отдаёт прямую ссылку на PNG в og:image.
  Ссылку на живой график (`/chart/…`) так забрать нельзя — там JS-приложение, а
  og:image у него стоковый; для неё из адреса читаются только тикер и таймфрейм.
- `max_tokens` для разбора — 4096: у моделей с рассуждением его токены тоже
  входят в лимит, и на насыщенном графике ответ занимает под 2000. При обрезке
  эндпоинт отвечает ошибкой, а не пустым результатом.
- Плечо (`Trade.leverage`, по умолчанию из `Account.defaultLeverage`, 5×) на риск
  не влияет: убыток при стопе считается от номинала позиции. Плечо определяет
  только маржу — `positionSize / leverage`, ту часть депозита, что реально уходит
  в сделку. На дашборде под бюджетом риска отдельная шкала «Маржа в сделках»,
  в форме — предупреждение, если маржа больше баланса.
- Лимит бюджета риска — поле `Account.riskLimitPct` (потолок суммарного риска
  открытых позиций в процентах от баланса, по умолчанию 3%), редактируется в
  `/settings`. Жёлтая зона начинается после 2/3 лимита.

### Состояние на клиенте и оптимистичные обновления

Страница сделки после первого SSR живёт в кеше TanStack Query (ключ
`['trade', id]`, `src/lib/query/`). Фиксации добавляются и удаляются
оптимистично: `onMutate` патчит кеш и делает снимок, `onError` откатывает,
`onSuccess` кладёт серверный ответ, `onSettled` сверяется. Локальный расчёт —
`src/lib/trade-local.ts` на той же `lib/trading-math`, поэтому после
подтверждения цифры не меняются. Новая сделка открывается как карточка на
месте формы: DTO считается локально, URL подменяется через `replaceState`,
POST уходит в фоне. Id сделок и фиксаций генерирует клиент (uuid), сервер
идемпотентен по ним. Запросы, зависящие от ещё не сохранённой сделки, ждут её
через `src/lib/query/pending.ts`. Ошибки не молчат: полоска с причиной,
«Повторить» и «Скрыть». Devtools Query открываются кнопкой слева внизу.

## Перенос истории из Google-таблицы

Разовая миграция старого журнала. Таблица должна быть открыта по ссылке —
экспорт CSV идёт без авторизации.

```bash
npx tsx scripts/import-sheet.ts <ссылка-на-таблицу>           # показать, что будет
npx tsx scripts/import-sheet.ts <ссылка-на-таблицу> --apply   # записать в БД
```

Результаты пересчитываются формулами приложения, а не берутся из колонок
таблицы, поэтому расходятся с ней в пределах копейки на округлении. Повторный
запуск безопасен: сделка с теми же входом, стопом и направлением пропускается.
Незакрытые сделки (сумма фиксаций не равна 100%) не переносятся.
